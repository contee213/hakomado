# 確認の手順

改修したとき、リリースの前に、何をどの順で確かめるかの手順。「いつものチェック」の観点を、手で確かめられる形にしたもの。

- YouTube のページの中で動く部分 (枠の中のプレイヤー・ライブチャット・同期・✨ 自動補正など) の確かめ方は [../tests/MANUAL.md](../tests/MANUAL.md) にある。ここでは、その外側をまとめる。
- ストアに上げる手順は [../CHROMEWEBSTORE.md](../CHROMEWEBSTORE.md) の「ストアに上げる手順」にある。
- 確かめた結果は PR の本文に書く。確かめなかったこと (例: いつもの Chrome では動かしていない) も書く。

## 1. 自動のテスト (改修のたび)

PR を出す前に、手元で通しておく。PR では GitHub Actions でも同じものが回り、通らないとマージされない。

| 何を | コマンド | 備考 |
| --- | --- | --- |
| 単体テスト | `npm test` | YouTube に触らない部分 (コード・バックアップ・レイアウト・文言など) |
| E2E テスト | `npm run test:e2e` | 拡張機能を入れたブラウザで、画面のボタン・ダイアログ・ツアー・視聴セッションを試す。外への通信は止めている。同梱の Chromium が起動しない環境では、`E2E_CHANNEL=msedge` を付けて Edge で回す |

- 不具合を直したときは、直す前のコードで失敗するテストを足す。
- 新しい決まり ([design-guide.md](design-guide.md)) に合わせて直したときは、決まりどおりに動くことを確かめるテストを足す。

## 2. 見直しの観点 (大きめの改修のたび)

差分を、次の観点で読み直す。見つけたものは直すか、直さない理由を PR に書く。

| 観点 | 見るところ |
| --- | --- |
| セキュリティ | 外から来た文字 (URL・コード・ファイル・ページの中身) をそのまま HTML に入れていないか。権限・ホスト権限・通信先が増えていないか (増えたら CHROMEWEBSTORE.md も直す)。Cookie を付けて送る先が増えていないか |
| フェールセーフ | 読み込みや通信に失敗したとき、途中で止まったときに、データが消えない・壊れないか。失敗したら、使う人が気づけるか |
| 消す操作 | 取り戻せないもの ([data-io.md](data-io.md) の「作ったもの」) を消す操作に、「元に戻す」か確認があるか |
| 要らないコード・重なったコード | 使われなくなった関数・文言・CSS が残っていないか。同じ処理が 2 か所にないか |
| 取り合い | 同じ保存先を、複数の処理が同時に書き換えないか (`navigator.locks` を使っているか) |
| 重複起動 | マルチビュー画面を複数のタブ・複数のウィンドウで開いたときに、お互いの内容を上書きしないか。通知や取得が二重にならないか |
| 文言 | 画面・乗せたときの説明・知らせ・README・CHROMEWEBSTORE.md で、ボタンの名前や言葉が同じか。日本語と英語の意味がそろっているか。古い名前や記号が残っていないか (`grep` で探す) |
| 設計の文書 | 画面遷移図・画面項目表・データの入出力・UI の不揃いの一覧を、同じ PR で直したか (`CLAUDE.md` の決まり) |

## 3. 入れたとき・消したとき・更新したとき (リリースの前)

まっさらな Chrome のプロファイル (ふだん使いとは別) で確かめる。

| 場面 | 手順 | どうなればよいか |
| --- | --- | --- |
| 初めて入れる | `chrome://extensions` で `extension/` を読み込み、ツールバーのアイコンを押す | マルチビュー画面が開き、使い方ツアーが 1 回だけ出る。同梱のチャンネルが入っている。service worker と画面のコンソールにエラーが出ない |
| リリース版を入れる | `node tools/build.js` で作った `dist/hakomado/` を読み込む (配る ZIP と同じ中身。HAKO-51) | エラーなく開き、上部バーの ⏱・☰、設定の「実験的な機能」、ヘルプの「アーカイブの同期再生」が出ない。`extension/` をそのまま読み込んだときは、設定で ⏱ アーカイブ同期を ON にできる |
| 2 回目に開く | 画面を閉じて、もう一度アイコンを押す | ツアーは出ない。前に枠へ入れた配信があれば、起動画面で再開を聞かれる |
| 更新する | 前の版を入れて使ってから、新しい版に入れ替える (`chrome://extensions` の再読み込み) | 設定・チャンネル・📌・視聴履歴・あとで見る・再生リスト・視聴セッションが残っている。ツアーは出ない。右クリックのメニューと取り込み用リンクが使える |
| 前の版のデータを読む | 前の版で作った視聴セットのコード・パック・バックアップを、新しい版で読み込む | そのまま読める。逆に、新しい版で作ったコードを前の版で読んでも壊れない (読めない項目は読み飛ばす) |
| 消す | 拡張機能を削除する | 開いていたマルチビュー画面が閉じる。YouTube のページに Hakomado のものが残らない (取り込み用リンクは YouTube の普通の再生リストとして開く) |
| 入れ直す | 削除してから入れ直し、前に書き出したバックアップを読み込む | 件数を見せて確かめたあと、書き出したときの内容に置き換わる |

## 4. 複数のタブ・ウィンドウ

| 場面 | 手順 | どうなればよいか |
| --- | --- | --- |
| 2 つのタブで開く | マルチビュー画面を 2 つ開き、それぞれ別の配信を入れる | お互いの枠の中身を上書きしない。共通の設定を片方で変えると、もう片方にもすぐ反映される |
| 右クリックで追加 | 2 つの画面を開いた状態で、YouTube の動画を右クリックして追加する | 最後に使った画面の空き枠に入る。その画面が 16 枠いっぱいなら、空きのある別の画面に入る。どれもいっぱいなら新しいタブで開く |
| 通知・配信状況の取得 | 2 つの画面を開いたまま数分置く | 通知が二重に出ない。配信状況の取得が二重にならない |

## 5. YouTube を使う確認 (大きく変えたとき・リリースの前)

[../tests/MANUAL.md](../tests/MANUAL.md) の表を上から順に確かめる。

- ふだん使いのプロファイル (ログイン中の YouTube アカウント) で確かめるときは、コメントの書き込み・高評価・チャンネル登録・設定の変更など、アカウントに残る操作をしない。
- バックアップの読み込みは、先に書き出してから試す。

## 6. 出す前に

- `manifest.json` の権限・ホスト権限・content scripts・通信先を変えたら、`CHROMEWEBSTORE.md` の「権限と理由」「外への通信」と、[privacy.md](privacy.md) を同じ PR で直した。
- 画面の言葉を変えたら、`CHROMEWEBSTORE.md` の掲載文 (日本語・英語) と README も直した。次にストアへ上げるとき、ダッシュボードの掲載文も貼り替える。
- 決めたことがあれば [decisions.md](decisions.md) に足した。
