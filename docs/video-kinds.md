# 動画の種類と判定

Hakomado が扱う YouTube の動画の種類と、それぞれをどこで・何で見分けているかのまとめ (2026-11-23 時点)。

## YouTube 側の区分け

チャンネルの投稿は、YouTube の仕組みの上で 3 つの再生リストに分かれている。どれも
`https://www.youtube.com/feeds/videos.xml?playlist_id=<接頭辞><チャンネル ID の 3 文字目以降>` で RSS (新しい順 15 件、ログイン不要) が取れる。

| 接頭辞 | 中身 | RSS のリンク | 備考 |
| --- | --- | --- | --- |
| `UULV` | ライブ配信 (配信予定・配信中・アーカイブ) | `/watch?v=` | 縦型の配信もここ。プレミア公開は入らない |
| `UULF` | 通常の動画 (MV・切り抜き・プレミア公開など) | `/watch?v=` | ショートは入らない |
| `UUSH` | ショート | `/shorts/` | 縦型の配信は入らない |

ほかの手がかり:

- `/shorts/<ID>` を開くと、ショートはそのまま開き、それ以外 (縦型の配信を含む) は `/watch` に転送される (303)
- サムネイル `i.ytimg.com/vi/<ID>/oardefault.jpg` はショートにだけある
- 動画ページの `liveBroadcastDetails` (開始・終了時刻) は、ライブ配信とプレミア公開にある。`isLiveContent` はライブ配信だけ true (プレミア公開は false)
- 縦型の配信は YouTube の上ではショートではなく、ふつうのライブ配信。縦長かどうかは RSS では分からず、動画ページ (プレイヤーの情報の各画質の幅・高さ。例: 720×1280) で分かる

## Hakomado の中での種類

### 最近の動画 (`favorites.js` の `fetchArchives`) — RSS で分かる種類

| `kind` | 取るところ | 判定 |
| --- | --- | --- |
| `live` | UULV | 配信のアーカイブ (縦型の配信も含む) |
| `video` | UULF | UULV に無いもの (プレミア公開・MV など) |
| `short` | UUSH | 自動再生でショートも流す設定のときだけ取る |

どれも再生数 0 (配信予定・公開予定) は除く。`list` には取った再生リスト (UULV / UULF / UUSH) を入れる。

### 枠の情報 (`content/watch-main.js` の `infoNow` → `hakomado:info`) — 枠で読み込んでから分かる種類

| 項目 | 値 | 判定 |
| --- | --- | --- |
| `kind` | `live` / `upcoming` / `archive` / `video` / `''` | プレイヤーの情報 (`isLive`・`isUpcoming`・`liveBroadcastDetails`・`isLiveContent`) |
| `vertical` | `true` / `false` / `null` | プレイヤーの情報の各画質の幅・高さ。無ければ再生中の映像 (広告中は見ない)。マルチビュー画面で、縦長と分かった枠を 9:16 に寄せるのに使う (設定が ON のとき) |

プレミア公開は `kind` が `archive` (公開が終わったあと) になる。

### 設定と使い道

| 設定 | 既定 | 効くところ |
| --- | --- | --- |
| 配信中が無いときは、最近の動画を流す | OFF | 自動再生で空き枠に最近の動画を入れる |
| 動画 (プレミア公開・MV など) も流す | ON | `kind: 'video'` を候補に入れる |
| ショートも流す | OFF | UUSH を取り、`kind: 'short'` を候補に入れる。縦型の配信はショートではなくふつうの配信なので、この設定に関係なく流す |
| 縦型の配信と分かったら、枠を縦長にする (設定の「表示」タブ) | OFF | 読み込んで `vertical: true` と分かった枠も 9:16 に寄せる。読み込んだ後に枠の大きさが変わるので既定は OFF |

ライブラリの「🎞 最近の動画」には UUSH の分は出さない (縦型の配信は出る)。

### 縦長の動画の見せ方 (`grid.js` の `isShortHint`・`videoInput`・`verticalFit`)

読み込んでから枠の形が変わらないよう、ショートの枠にするかは**読み込む前**に分かる手がかりだけで決め、枠の状態 `short` に入れる (保存される)。
プレイヤーが知らせる `vertical` で縦長にするのは、設定「縦型の配信と分かったら、枠を縦長にする」が ON のときだけ (`isVerticalTile`)。

- 手がかり: `/shorts/` の URL。ショートの再生リスト (UUSH) から入れる動画 (自動再生でショートも流す設定のとき) は、`/shorts/<ID>` の URL で枠に入れる (`videoInput`)。自分で `/shorts/` の URL を貼ったときもショートの枠
- 枠の URL は履歴・再生リストにも残るので、そこから開き直してもショートの枠になる
- タイトル (#shorts など) では判定しない。縦型の配信はショートではない (UULV に入る) ので、ふつうの 16:9 の枠 (中は左右に黒帯)。設定が ON なら、読み込んで縦長と分かってから 9:16 に寄せる
- `/watch?v=` の URL で貼ったショート・右クリックの「空き枠に追加」・共有コードの読み込みは、読み込む前に分からないのでふつうの枠
- 標準表示: `solveTracks` (`layouts.js`) に枠ごとの目標の縦横比を渡し、ショートの枠は 9:16、ほかは 16:9 として列幅・行高を解き直す。1×2 で片方がショートなら、その列が細くなり、もう片方が大きくなる
- 同じ列・行に横長の枠があると、両方の間の比で止まる (例: 2×2 で対角にショートが 2 枠)。そのため、映像が画面に出る広さの合計が今 (どれも 16:9) より広くなるときだけ解き直した形を使う
- PinP (枠が重なる) は小窓とメインの形が絡むので、解き直さない
- メイン拡大: 縦長の枠があるときは使わず、標準と同じく 9:16 に寄せる
- 縦長の枠が空いた・入れ替わった・設定を OFF にしたら、元の 16:9 に戻す
- レイアウトの定義 (`LAYOUTS`) と共有コードは変えないので、`web/` (Hakomado Feed) の表示・読み込みには影響しない

## まだ決めていないこと

- ショートの枠を同じ列・行に寄せる並べ替え (自動再生でショートの枠が横長の枠と同じ列・行に入ると、9:16 に寄せきれない)
- `/watch?v=` で入れたショートを読み込む前に見分ける方法 (右クリックの追加・共有コードなど)
- 縦長の枠を持つレイアウト (横長 N + 縦長 M など) を足すか
